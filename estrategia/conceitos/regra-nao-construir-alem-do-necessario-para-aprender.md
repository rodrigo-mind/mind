# Não construa nada além do necessário para aprender

## Regra

Remova qualquer função, processo ou esforço que não contribua diretamente para o aprendizado que você procura.

## Por quê

Para o livro, todo trabalho além do necessário para começar a aprender é desperdício, por mais importante que tenha parecido. Cada função extra atrasa o teste, e adiar o teste custa aprendizado e tempo de ciclo. Construir primeiro para ver depois como o cliente reage é o caminho de maior desperdício: se ninguém quer, tudo foi gasto à toa. No exemplo do livro, o time tinha feito integração com mais de uma dúzia de redes quando talvez uma, ou nenhuma, bastasse para descobrir que a ideia estava errada.

## Quando não vale

- Defeitos que atrasam a evolução do produto atrapalham o aprendizado e não devem ser tolerados; o livro promete tratar disso na Parte Três.
- Não é licença para trabalho desleixado.
- Se a função é o próprio objeto do teste (o que o cliente valoriza), ela entra.

## Como verificar

Para cada item do escopo, o time escreve qual hipótese ele testa. Item sem resposta sai.
